# Accounts and organizations

import { OneDoor } from "../components/account-diagram";

## One door

<OneDoor />

absqir has one sign-in page. It asks for an email address first, then
decides what comes next:

- A known email with a password asks for that password. A link on the same
  screen sends a 6 digit code instead, which also sets a new password.
- An unknown email that may register receives a 6 digit code. The code
  creates the account and opens onboarding: name and password, an optional
  picture, then the organization.
- An unknown email that may not register sees a note that it needs an
  invitation.

Codes and invitations travel by email, so `RESEND_API_KEY` is required in
production. See [Configuration](/configuration).

## Who may register

The first account on a fresh instance is the operator. It can create
organizations. After that, an email can register only when:

- an organizer invited it (the invitation email carries the link),
- it arrived from the public page of an event that takes registrations
  (see [Events](/sessions#public-registration)), or
- the operator set `REGISTRATION_OPEN=true`, which lets any email register
  and create organizations.

An account without an organization lands on a page that lists its pending
invitations and, when allowed, a form to create an organization.

## Your account

**Settings** is one page for everyone, whatever their role. A list of
sections sits on the left. Owners and admins see the organization sections,
**Members**, **Invitations** and **Organization**. Everyone sees the
sections about themselves:

- **Profile**: the name and the picture organizers see, and the email. A
  new address receives a 6 digit code. Nothing changes until the code is
  entered, and an address that another account uses is refused.
- **Preferences**: choices that belong to the browser, not to the account.
  The theme (system, light or dark) and animation (follow the device, on,
  or off). A phone and a room screen can differ.
- **Notifications**: where absqir reaches this account. See
  [Notifications](/notifications#where-they-go).
- **Security**: the password, with an option to sign out every other
  device, and the devices. Every browser signed in as this account shows as
  a card with the browser, the platform, the last visit and the address.
  This device comes first, then the most recent. The grid scrolls in its
  own box and shows eight cards at a time; **Load more** adds the next
  eight. Each card has a sign-out button, and the section has one for all
  the others.

**Settings** sits in the sidebar under **Other**, for every role. The
account menu in the app bar opens **Profile** and **Preferences**. The old
`/account` address lands on the profile. The link at the bottom of the
sidebar opens the absqir repository on GitHub in a new tab.

The sidebar remembers whether you left it open or collapsed. The choice
lives in a cookie, so the next page paints it that way at once. The app
bar with the sidebar toggle, the page name, the bell and the account menu
stays at the top of the page while you scroll. On a phone the same bar
sits at the bottom of the screen, where a thumb reaches it.

Every account gets a colored circle with its initials until it has a
picture. The color comes from the name, so the same name always shows the
same color, and the letters keep a contrast above 7:1 in both themes.

A change of email or password needs a session read less than an hour ago.
An older session is told to sign in again first. Deleting an account is not
offered yet.

Tabs, filters and searches live in the address bar: `/sessions?scope=past`,
`/people?q=grace`, `/settings?tab=security`. A link carries the view with
it, and the back button returns to the previous one.

## Organizations and roles

Every resource belongs to an organization. An account can belong to several
and switches between them in the sidebar. Each membership carries one role:

| Role        | What it can do                                                       |
| ----------- | -------------------------------------------------------------------- |
| `owner`     | Everything, including deleting the organization and naming owners.   |
| `admin`     | Manage people, groups, invitations, members, and settings.           |
| `organizer` | Read the directory, run events, scan at the door, decide on leave.   |
| `member`    | See their own events and history, and ask for leave.                 |

## People and groups

The directory holds every person the organization expects to see, with an
optional email and an optional identifier such as an employee number. A
person exists before they have an account: add them by hand, or import a
CSV with `name`, `email`, and `identifier` columns. A person with an email
can be invited; when they accept, their account links to that directory row.

Groups collect people: a team, a division, a class, a cohort. An event
expects a group, and whoever does not check in is marked absent.

## From the CLI

Create an account that skips onboarding. It can create organizations when
you pass `--create-orgs`:

```bash
npx absqir admin create --email guru@example.com --name "Guru" --create-orgs
```

Let an existing account create organizations, or take that back:

```bash
npx absqir admin promote --email guru@example.com
npx absqir admin promote --email guru@example.com --revoke
```

Add an existing account to an organization by its slug:

```bash
npx absqir member add --email guru@example.com --org yayasan-x --role organizer
```
